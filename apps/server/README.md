# Phase 5 · 서버 권위 1대1 수직 시연판

기존 Phase 4 로컬 데모와 분리된 `/online.html` 시연 화면입니다. 두 접속자가 같은 Colyseus Room에 들어가면 서버만 `battle-core.step()`을 100ms tick으로 실행합니다. 접속 순서로 blue/red 좌석을 배정하고 각자 2개 부대를 지휘합니다. 시연 편성은 양측 창병·궁병 각 20명, seed 41, 시작 Lv.16으로 고정하며 운영 밸런스 확정이 아닙니다.

## 실행

저장소 루트에서 Node 22.13 이상으로:

```sh
npm ci
npm run build
node apps/server/dist/index.js
```

별도 터미널에서 `npm run dev --workspace @roan/client`을 실행하고 표시된 주소의 `/online.html`을 두 브라우저 창에서 엽니다. 서버 기본 포트는 2567이며 `PORT`로 바꿀 수 있습니다. 클라이언트 주소가 다르면 `?server=ws://HOST:PORT`를 사용합니다.

## Render 배포

현재 선택한 배포 대상은 Render 단일 네이티브 Node 서비스입니다. [Render 설정 안내](../../docs/network/RENDER_DEMO_v0.1.md)와 루트 `render.yaml`을 사용합니다. 계정 DB는 `/var/data` 영구 디스크에 저장하고, 배정된 HTTPS 원본은 `RENDER_EXTERNAL_URL`에서 자동 허용합니다. 명시적 `CLIENT_ORIGINS`가 있으면 우선합니다. Google 로그인은 보류하며 실제 배포·외부 검증은 계정 연결 후 진행합니다. Railway 설정과 Docker/Caddy 구성은 대안으로 유지합니다.

## 외부 시연 준비와 장애 검사

[외부 시연 문서](../../docs/network/EXTERNAL_DEMO_v0.1.md)의 Docker/Caddy 구성과 같은 원본 정적 제공을 추가했습니다. `npm run test:network`는 빌드된 화면에서 지연·일시 단절·실제 30초 예약 만료를 검사합니다. 외부 배포 이후에는 `DEMO_URL=https://도메인 npm run test:remote`로 실제 원격 SDK 접속을 검사할 수 있습니다. 외부 서버·도메인이 없어 실제 배포 및 공인 HTTPS는 아직 미검증입니다.

## 권위와 검증

- Google 로그인과 게스트 접속을 함께 제공하며 서버가 계정을 검증합니다. [설정과 인증 범위](../../docs/network/GOOGLE_AUTH_v0.1.md)를 참고하세요. `GOOGLE_CLIENT_ID` 미설정 시 게스트 이용을 유지합니다. 계정 식별 정보는 SQLite에 보관하며 앱 세션은 메모리에만 유지합니다. 서버 재시작 후 재로그인하면 같은 계정 ID를 사용합니다.

- 클라이언트는 명령 의도만 보냅니다. 서버는 Colyseus 세션 ID로 좌석을 찾아 `playerId`, `seq`, `requestedTick`을 채웁니다. 타인 부대·장수 명령을 즉시 거부하고 유효한 입력은 다음 tick에 코어가 다시 검증합니다.
- 최초 접속·재접속에는 해당 국가의 관측 상태만 보내고, 이후 200ms마다 관측 상태의 변경된 필드만 전송합니다. 클라이언트는 tick·국가별 상태 해시를 검증하며 기준 tick이 맞지 않으면 관측 스냅샷을 다시 요청합니다. 렌더링 위치만 전후 서버 상태 사이에서 보간합니다. `battle-core`의 전체 상태는 서버에만 남습니다.
- 연결이 끊기면 최대 30초간 좌석을 보존하고 경기 tick을 멈춥니다. 같은 탭의 새로고침은 `sessionStorage`의 재접속 토큰으로 원래 진영에 복귀합니다. 30초가 지나면 좌석을 해제합니다.
- `npm run test:online`은 실제 서버와 두 SDK 접속으로 같은 Room·좌석·타인 명령 거부·관측 델타 해시와 서로에게 보이는 부대 값의 일치를 확인합니다.
- `npm run test:browser:online`은 두 실제 페이지의 상태 일치와 명령 거부를 검사합니다. Chromium이 설치된 환경에서 실행해야 합니다.
- `npm run test:online:soak`은 실제 서버와 SDK 연결 6개를 900tick 이상 실행합니다. 반복 명령, 타인 명령·잘못된 형식 거부, 델타 1개 의도적 누락 후 관측 스냅샷 복구, 연결 1개 강제 종료 후 같은 좌석 자동 복귀와 국가별 해시 일치를 검사합니다. 빠른 개발 점검은 `ONLINE_SOAK_TICKS=100 npm run test:online:soak`으로 실행할 수 있으며 90초 인수 검사를 대체하지 않습니다.

## 온라인 전술과 3대3 로비

- `/online.html`에서 자신의 부대와 적 목표를 클릭하거나 선택하고 이동·공격 이동·후퇴·태세·진형·장수 재배속·Q/W/R 명령을 보낼 수 있습니다. 좌표는 시연 지도상의 타일 단위로 입력하며 실제 명령 유효성은 서버와 전투 코어가 판단합니다. HUD는 부대 병력·HP·사기·전열, 장수 상태·쿨다운, 최근 사건을 표시합니다.
- `/online.html?mode=3v3`은 두 국가에 3좌석씩 번갈아 배정합니다. 첫 접속자가 로비장이며 양쪽에 인간이 최소 1명씩 접속하면 시작할 수 있습니다. 빈자리는 서버 소유 AI 부대가 됩니다. AI는 시작 시 중앙 경로로 공격 이동하고 전투 코어의 기본 교전에 맡깁니다. Q/W/R·진형 선택·전략적 후퇴를 AI가 독단적으로 사용하지 않습니다.
- 편성(각 플레이어 2부대, 부대당 20명), 시작 위치, AI의 중앙 이동 경로는 이 시연의 재현용 가정이며 운영 밸런스가 아닙니다. 경기 시작 후 신규 인간 참가자는 받을 수 없고, 기존 참가자의 30초 재접속은 유지합니다. 연결 만료 뒤 좌석은 AI로 남습니다.
- 빠른 접속은 참여 가능한 Room에 입장합니다. `새 초대 전용 경기`는 별도 Room을 만들고 빠른 접속 목록에서 제외합니다. 서버가 발급한 초대 키를 링크의 `#invite=`에 포함하며, Room ID만 있거나 키가 다르면 좌석·상태를 보내기 전에 입장을 거부합니다. 새로고침은 기존 30초 재접속 예약을 사용합니다.
- 로비장은 `초대 링크 재발급`으로 이전 링크의 신규 입장을 막을 수 있습니다. 이미 입장한 사용자의 좌석·재접속은 유지합니다. 초대 키는 Room 목록과 전투 상태에 포함하지 않습니다. 링크 소지자는 빈자리에 입장할 수 있으므로 Google 계정 신원 확인은 선택 사항이며, 계정별 초대 제한·계정 차단 기능은 별도입니다.
- 초대 전용 3대3 로비에서 시작 전 로비장은 다른 인간 참가자를 내보낼 수 있습니다. 접속이 끊겨 예약 중인 좌석도 해제하며 해당 세션의 재접속 예약을 취소합니다. 초대 키를 함께 갱신해 이전 링크의 입장을 막고 남은 참가자에게 새 링크를 전달합니다. 경기 시작 후·빠른 접속 방·자기 자신·AI/빈자리에는 적용하지 않습니다. 계정 차단 기능은 아니므로 새 링크를 다시 받은 사람은 게스트로 입장할 수 있습니다.
- `경기 나가기`는 즉시 좌석을 해제하고 로비장을 남은 접속자에게 넘깁니다. 시작한 3대3 경기에서는 빈자리를 기존 AI 흐름이 이어받습니다. 명령 번호는 좌석별로 유지해 새 참가자나 AI의 첫 명령이 중복 번호로 거부되지 않게 합니다. 로비에는 연결/재접속 대기 상태를 표시하며 접속이 끊긴 참가자가 남아 있으면 시작을 거부합니다.

## 미구현

다중 서버 계정 운영·진영 선택·계정별 차단/초대 관리·정식 매치메이킹·Colyseus Schema 기반 동기화·정식 승리 규칙은 아직 없습니다. 현재 필드 델타는 `packages/protocol`의 작은 전송 규약입니다. 국가 공유 시야는 10타일 실험값으로 적용하며 숨겨진 적은 마지막 위치와 관측 tick만 표시합니다. 자세한 규칙·설정 변경은 [시야 문서](../../docs/network/VISIBILITY_v0.1.md)를 참고하세요. 이 시연판은 공개 서비스 배포용이 아닙니다.
