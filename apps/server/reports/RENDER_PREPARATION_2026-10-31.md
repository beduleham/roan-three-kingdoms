# Render 전환 준비 검증 · 2026-10-31

## 변경

- `render.yaml`: 네이티브 Node 24.22.1 웹 서비스 한 개, Singapore, 0.5 CPU/512MB 유료 플랜, 수동 재배포, `/healthz`, `/var/data` 1GB 디스크. 기존 npm 빌드/Node 시작 명령을 사용한다.
- `apps/server/src/auth.ts`: Render가 제공한 HTTPS `RENDER_EXTERNAL_URL`의 원본만 자동 허용한다. 명시적 `CLIENT_ORIGINS`가 우선하며 잘못된 플랫폼 URL은 거부한다.
- `apps/server/test/origins.test.ts`: 실제 HTTP 요청으로 배정 원본 허용·다른 서비스 거부·운영자 설정 우선·HTTP/잘못된 URL/자격 정보 포함 URL 거부를 검사한다.
- Render 안내, 외부 배포 안내, 기존 Railway 안내, 서버 README, 개발 체크리스트: 현재 대상을 Render로 변경하고 Railway는 대안 기록으로 유지한다. Dockerfile과 전투 코드는 변경하지 않았다.

## 실제 배포 경계

현재 공식 Render 상태 페이지는 정상 운영으로 표시됐지만 이는 개별 가입·결제·저장소 권한을 검증한 결과가 아니다. Render 앱 설치/계정 연결이 확인되지 않아 서비스·디스크·공개 주소를 생성하지 않았다. Render API Blueprint 승인, 실제 디스크 쓰기 권한, 원격 HTTPS/WSS와 두 외부 브라우저 경기 검증도 남아 있다. 로컬 YAML 파싱을 클라우드 승인으로 표현하지 않는다.

네이티브 Node를 사용하므로 Railway 전용 root UID 변수를 넣거나 Caddy 서비스를 추가하지 않는다. 영구 디스크가 있는 서비스는 단일 인스턴스로 유지한다. 재배포 시 경기·메모리 세션·예약 좌석은 보존되지 않는다. 요금은 서비스 생성 전에 실제 Render 계정에 표시된 금액을 확인해야 한다. Google 로그인은 보류하며 전투 규칙·밸런스·승패 규칙을 추가 확정하지 않았다.
