# 전멸 기준 로컬 시험 결과 v0.1

## 구현 범위

현재 로컬 데모의 한쪽 부대가 모두 HP 0이 되면 해당 tick 처리를 끝낸 후 자동 정지한다. 양쪽 모두 전멸하면 동시 전멸로 기록한다. 부대 하나의 전멸, 사기 패주, 전열 붕괴, 장수 부상만으로는 종료하지 않는다. 이후 재개와 전투 명령은 막고 상태 확인·카메라 이동·로그 저장·재시험은 허용한다.

이것은 TRD의 국가 점수·거점·15분 판정·연장전·천하통일 규칙을 구현한 것이 아니다. 현재 부대 2개 대 2개의 로컬 전멸 시험을 끝내는 어댑터 정책이며 battle-core에는 승리 필드·승리 이벤트를 추가하지 않았다.

## 결과 화면

- 양피지 계열 바탕과 붉은 終 인장을 사용한 결과 영역. 전장 화면을 덮지 않아 종료 상태를 확인할 수 있다.
- 종료 시각·tick, 진영별 잔존/시작 병력, 전멸 부대 수, Q/W/R 승인 횟수, 돌격 적중 횟수.
- 병력은 기존 livingSoldiers와 동일한 HP 기반 반올림 규칙(올림)을 사용한다. 승인 횟수는 SKILL_CAST 사건 수이며, 대상 부대 수가 많아도 한 시전은 한 번으로 센다. 거부된 명령과 UI 클릭 수는 포함하지 않는다.
- 같은 편성으로 재시험: 실제 시험에 적용된 병종·실험 증강 설정으로 tick 0에서 일시정지 상태로 시작한다. 적용하지 않은 드롭다운 변경은 섞이지 않는다. 기존 전투 명령·기록·결과는 초기화한다.
- 편성 변경: 설정 영역을 연다. 편성 적용 전에는 종료 기록을 유지한다.
- 로그 저장: 기존 전체 입력·사건 해시를 가진 재현 로그를 다운로드한다. 결과 자체를 별도 보상/공적/경험치로 저장하지 않는다.

## 수정 파일

- `apps/client/src/test-result.ts`: 표시용 결과 요약과 로컬 종료 판정.
- `apps/client/src/session.ts`: 완결된 tick 이후 정지, 추가 명령/재개 차단과 재시험 초기화.
- `apps/client/src/main.ts`, `style.css`: 결과 UI, 전투 명령 비활성화, 편성 변경/재시험/로그 연결. 이전 그래픽 작업에 맞춰 병종 안내 문구도 갱신했다.
- `apps/client/test/test-result.test.ts`, `session.test.ts`: 세 종료 유형, 비종료 상태, 시전 집계, 동시 전멸 후 추가 tick 차단과 리플레이.
- `apps/client/e2e/demo.spec.mjs`: 실제 UI로 교전하여 전멸 후 결과·정지·로그 다운로드·재시험을 검증한다. 테스트용 상태 변경 API나 가짜 종료 입력은 추가하지 않았다.

## 검증과 남은 기획

- `npm run typecheck`: 통과.
- `npm test`: 285개 통과.
- `npm run build`: 통과(기존 대형 번들 경고 유지).
- `npm run format:check`: 통과.
- 실제 Chromium 단독 결과 검사: 정상 교전 후 자동 정지·결과·재시험 통과. 최종 전체 검사에서는 다운로드한 JSON 자체를 다시 재생해 해시를 비교한다.

국가 점수와 거점의 정식 종료, 시간 제한과 교착 해소, 병력 충원/재출전이 있는 경기의 전멸 처리, 보상/성장/다음 경기 흐름은 별도 설계·구현 대상이다. 전투 수치나 검증된 밸런스는 확정하지 않았다. 특정 시험 편성의 짧은 전투 시간은 목표 경기 시간이나 병종 상성의 검증 결과를 뜻하지 않는다.

## 최종 브라우저 결과

실제 Chromium: 최종 소스로 16개 검사 모두 통과. 기존 90초 UI/헤드리스 상태·이벤트 해시 일치와 새 전멸 결과 흐름을 포함한다. 새 검사는 UI로 정상 교전한 뒤 자동 정지, 종료 후 추가 tick 차단, 실제 다운로드 JSON 재생 해시 일치, 미적용 편성 변경을 배제한 같은 편성 재시험을 확인했다.
