# 저장 전투 로그 재현 검증 v0.1

## 기능

상단 ‘저장 로그 검증’에서 현재 2대2 데모가 다운로드한 JSON을 선택하면 별도 Web Worker에서 입력을 재현한다. 최종 상태와 전체 사건의 저장된 해시를 각각 재현 값과 비교한다. 두 값 모두 같으면 재현 일치, 하나라도 다르면 재현 불일치로 표시한다. 현재 플레이 세션의 상태·입력·편성에는 불러온 상태를 적용하지 않는다.

- 지원 버전: 현재 `DEMO.version`의 tick 0 초기 상태를 포함한 2플레이어·4부대·2장수 형식.
- 필수 항목: version, initial, frames, stateHash, eventHash.
- 초기 상태는 저장된 설정·시드·시나리오를 createBattle에 다시 통과시켜 정규 초기 상태와 같음을 확인한다. 매 명령도 기존 commandSchema로 검사한다.
- JSON 파싱 오류, 버전, 필수 형식, 초기 상태, 입력 형식, 재현 실행 오류를 구분한다.
- 최종 상태·사건 해시의 저장 값/재현 값을 함께 보여준다. 시드·tick·입력 수를 표시한다.
- 검증 취소와 새 파일 선택 시 이전 Worker를 종료한다. 작업 세대 ID를 확인해 늦은 결과가 새 파일 결과를 덮어쓰지 않도록 한다.
- 파일명은 텍스트로 표시하고 불러온 문자열을 HTML 코드로 실행하지 않는다.

## 실행 한도

`replay-policy.ts`에 검증 작업 한도를 둔다. 전투 밸런스나 승리 조건이 아니다.

- 파일 10MiB, 입력 기록 15,000tick, tick당 명령 64개, 전체 명령 20,000개.
- 증강 정의 최대 32개, 초기 안전지대 최대 4개.
- Worker 실행 30초를 넘으면 종료한다. 파일 읽기 중에도 사용자가 취소할 수 있다.

## 수정 파일

- `apps/client/src/replay-policy.ts`: 검증 작업 한도.
- `apps/client/src/replay-validation.ts`: 파싱·초기 복원·명령 검증·재현 대조.
- `apps/client/src/replay-worker.ts`: 화면과 분리된 재현 작업.
- `apps/client/src/replay-ui.ts`: 파일 선택·작업 종료·결과 표시.
- `apps/client/src/main.ts`, `style.css`: 검증 진입과 화면 연결.
- `apps/client/test/replay-validation.test.ts`: 실제 로그·초기 증강·두 종류 해시 불일치·형식·초기 상태·입력·작업 한도와 현재 세션 불변성.
- `apps/client/e2e/demo.spec.mjs`: 실제 다운로드 파일 검증, 상태 불일치, JSON 오류, 취소/교체와 이전 결과 차단.

## 검증과 범위

- `npm run typecheck`: 통과.
- `npm run build`: 통과. 검증 Worker가 별도 번들로 생성된다. 기존 대형 게임 번들 경고는 남아 있다.
- `npm run format:check`: 통과.
- 실제 Chromium 단독 검사 2개: 다운로드 파일 재현 일치/불일치/JSON 오류, 장시간 작업 취소/교체, 현재 전투 기록 불변성 통과.

이 기능은 현재 엔진이 같은 입력을 같은 결과로 재현하는지 검사한다. 시각적 리플레이 재생·탐색·멀티플레이 서버 검증·자동 버전 마이그레이션은 아직 구현하지 않았다. 엔진 변경이나 저장 내용 변경으로 불일치할 수 있다. 사용한 FNV 지문은 회귀 비교용으로, 파일 작성자 인증이나 암호학적 무결성 보증을 제공하지 않는다. 전투 수치나 권위 경계는 바꾸지 않았다.
