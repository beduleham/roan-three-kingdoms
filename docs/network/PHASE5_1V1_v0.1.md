# Phase 5 · 서버 권위 1대1 수직 시연판 v0.1

## 목적과 범위

Phase 4 로컬 데모의 결정적 `battle-core`를 서버 Room에서 실행하고, 두 접속자가 서로 다른 진영의 부대를 지휘하는 최소 온라인 경기를 검증한다. 기존 로컬 데모의 편성·결과 UI는 변경하지 않으며 별도 `/online.html`에서 시연한다.

## 구현 결정

- 접속 순서대로 blue와 red 좌석 하나씩 배정. 각 진영은 창병·궁병 20명씩 2부대. seed 41과 시작 Lv.16은 시연 가정이며 운영 밸런스가 아니다.
- Colyseus Room이 100ms마다 코어 `step()`을 호출. 두 좌석이 채워지기 전과 한 좌석이 떠난 뒤에는 tick을 멈춘다.
- 클라이언트가 보낸 JSON은 명령 의도만 포함한다. Room 세션 ID에서 소유자를 찾고 서버가 `playerId`, `seq`, `requestedTick`을 채운다. 형식·소유권을 경계에서 검사하고 코어가 다음 tick에 다시 검증한다.
- 최초 접속·재접속에는 전체 상태를 보내고, 이후 200ms 간격(5Hz)으로 변경된 필드의 경로와 값만 전송한다. 클라이언트는 기준 tick·해시 불일치 시 전체 상태를 다시 요청한다. 전투 상태는 서버 권위로 유지하며 클라이언트는 직전/현재 위치를 화면에만 200ms 보간한다.
- 비정상 연결 종료 후 30초 동안 좌석을 예약하고 tick을 멈춘다. 동일 탭의 새로고침은 SDK 재접속 토큰으로 같은 세션·진영에 복귀한다. 예약 만료·정상 이탈 후에는 좌석을 해제한다.
- Room은 최대 2접속과 접속자당 초당 20개 메시지 제한을 둔다. 후자는 네트워크 실험 보호 설정으로 전투 밸런스 값이 아니다.

## 검증

- 타입 검사·자동 테스트·빌드와 `npm run test:online`의 실제 서버/두 SDK 접속 검사.
- `npm run test:browser:online`의 실제 두 페이지 접속, 동일 상태 해시·병력 HUD, 타인 부대 명령 거부, 새로고침 좌석 복귀, 델타 수신·화면 보간 검사.
- 기존 `npm run test:browser`의 로컬 데모 회귀 유지.

## 다음 시연 확장: 온라인 전술과 3대3

- 온라인 HUD와 조작 패널에 이동·공격·공격 이동·후퇴·태세·진형·장수 재배속·Q/W/R을 추가. 최종 상태 변경과 스킬 조건·쿨다운은 서버/코어가 판단한다.
- 별도 `battle_3v3` Room: blue/red 각 3좌석, 접속 순서대로 교대 배정. 첫 접속자가 시작을 요청하고 양국에 사람이 최소 한 명씩 있어야 한다. 시작할 때 빈자리는 AI로 채운다.
- AI는 재현용 중앙 경로로 공격 이동한 뒤 기존 코어의 기본 교전을 수행한다. 전략적 후퇴·진형 선택·Q/W/R은 스스로 결정하지 않는다. 위치와 경로는 밸런스 확정이 아닌 시연 가정이다.
- 인간의 부대는 세션 소유권으로 검증한다. 같은 국가의 다른 사람이나 AI의 부대도 조작할 수 없다. 시작 후 신규 접속은 제한하고 기존 좌석의 재접속만 허용한다.
- 빠른 접속과 별개로 초대 전용 Room을 만들고 링크의 Room ID로만 입장할 수 있게 한다. 초대 전용 Room은 빠른 접속 후보에서 제외한다. 초대 링크는 게스트 편의 기능이며 계정 인증·초대 권한 검증은 아니다.

## 명시적 미구현

Colyseus Schema 기반 동기화, 계정 인증·초대 권한 관리·정식 매치메이킹, 전장의 안개, 국가 점수·거점 승리, 배포·운영은 다음 단계다. 30초 이후 좌석 복구는 보장하지 않는다. 접속 순서 좌석은 시연 전용 가정이다.
