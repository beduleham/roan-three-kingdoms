# Phase 5 · 서버 권위 1대1 수직 시연판 v0.1

## 목적과 범위

Phase 4 로컬 데모의 결정적 `battle-core`를 서버 Room에서 실행하고, 두 접속자가 서로 다른 진영의 부대를 지휘하는 최소 온라인 경기를 검증한다. 기존 로컬 데모의 편성·결과 UI는 변경하지 않으며 별도 `/online.html`에서 시연한다.

## 구현 결정

- 접속 순서대로 blue와 red 좌석 하나씩 배정. 각 진영은 창병·궁병 20명씩 2부대. seed 41과 시작 Lv.16은 시연 가정이며 운영 밸런스가 아니다.
- Colyseus Room이 100ms마다 코어 `step()`을 호출. 두 좌석이 채워지기 전과 한 좌석이 떠난 뒤에는 tick을 멈춘다.
- 클라이언트가 보낸 JSON은 명령 의도만 포함한다. Room 세션 ID에서 소유자를 찾고 서버가 `playerId`, `seq`, `requestedTick`을 채운다. 형식·소유권을 경계에서 검사하고 코어가 다음 tick에 다시 검증한다.
- 최초 접속·재접속에는 국가별 관측 상태만 보내고, 이후 200ms 간격(5Hz)으로 해당 관측 상태의 변경 필드만 전송한다. 클라이언트는 기준 tick·국가별 해시 불일치 시 관측 스냅샷을 다시 요청한다. 전투 상태는 서버 권위로 유지하며 클라이언트는 직전/현재 위치를 화면에만 200ms 보간한다. [국가 공유 시야](VISIBILITY_v0.1.md)는 10타일 실험값이며 숨겨진 적은 마지막 위치·관측 tick만 전송한다.
- 비정상 연결 종료 후 30초 동안 좌석을 예약하고 tick을 멈춘다. 동일 탭의 새로고침은 SDK 재접속 토큰으로 같은 세션·진영에 복귀한다. 예약 만료·정상 이탈 후에는 좌석을 해제한다.
- Room은 최대 2접속과 접속자당 초당 20개 메시지 제한을 둔다. 후자는 네트워크 실험 보호 설정으로 전투 밸런스 값이 아니다.

## 검증

- 타입 검사·자동 테스트·빌드와 `npm run test:online`의 실제 서버/두 SDK 접속 검사.
- `npm run test:browser:online`의 실제 접속, 같은 국가 해시·양측이 함께 보는 부대 값 일치, 타인 부대/시야 밖 적 명령 거부, 새로고침 좌석·관측 기억 복귀, 델타 수신·화면 보간 검사.
- 기존 `npm run test:browser`의 로컬 데모 회귀 유지.
- `npm run test:online:soak`: 실제 서버·6 SDK 연결·900tick, 같은 국가 안에서 동일 tick 관측 해시 대조, 명령 반복·입력 거부, 패치 누락 재동기화와 강제 연결 종료 자동 복귀 검사. 델타의 기준 tick·증가 방향·내용 해시 검사 코드는 브라우저와 공유한다.
- 이 검사는 전투 상태의 복구를 검증한다. 끊긴 동안의 사건 로그 재전송·완전한 온라인 리플레이, 실제 인터넷 지연 분포나 운영 부하 한계는 별도 검증이다.

## 다음 시연 확장: 온라인 전술과 3대3

- 온라인 HUD와 조작 패널에 이동·공격·공격 이동·후퇴·태세·진형·장수 재배속·Q/W/R을 추가. 최종 상태 변경과 스킬 조건·쿨다운은 서버/코어가 판단한다.
- 별도 `battle_3v3` Room: blue/red 각 3좌석, 접속 순서대로 교대 배정. 첫 접속자가 시작을 요청하고 양국에 사람이 최소 한 명씩 있어야 한다. 시작할 때 빈자리는 AI로 채운다.
- AI는 재현용 중앙 경로로 공격 이동한 뒤 기존 코어의 기본 교전을 수행한다. 전략적 후퇴·진형 선택·Q/W/R은 스스로 결정하지 않는다. 위치와 경로는 밸런스 확정이 아닌 시연 가정이다.
- 인간의 부대는 세션 소유권으로 검증한다. 같은 국가의 다른 사람이나 AI의 부대도 조작할 수 없다. 시작 후 신규 접속은 제한하고 기존 좌석의 재접속만 허용한다.
- 빠른 접속과 별개로 초대 전용 Room을 만든다. 초대 전용 Room은 빠른 접속 후보에서 제외하고 서버가 생성한 256비트 키를 `onAuth`에서 검사한다. 링크의 Room ID만으로는 입장할 수 없다. 생성자만 일회용 생성 증명으로 첫 입장을 허용하고, 이후 신규 입장은 현재 초대 키를 요구한다.
- 로비장만 키를 재발급할 수 있다. 이전 키로 신규 입장은 거부하되 기존 참가자와 재접속 예약은 유지한다. 키는 전투 상태/Room 목록에 넣지 않고 인증된 접속자에게만 제공한다. URL fragment에 보관하고 HTTP query에는 넣지 않는다. 계정별 신원 확인과 계정 차단은 별도 범위다.
- 초대 전용 3대3에서 시작 전 로비장은 타인의 인간 좌석을 해제할 수 있다. 제거한 세션의 재접속 예약을 취소하고 초대 키를 갱신해 남은 참가자에게만 보낸다. 빠른 방·시작 후·자기 자신·빈자리 제거는 거부한다. 계정 차단이 아닌 세션 제거이므로 새 키를 전달받으면 새 게스트로 입장할 수 있다.
- 정상 나가기는 즉시 좌석을 해제하고 연결 중인 다음 참가자에게 로비장을 넘긴다. 끊긴 좌석이 남은 로비는 시작을 거부한다. 좌석별 명령 번호는 세션 교체·AI 인계에도 유지한다.

## 명시적 미구현

Colyseus Schema 기반 동기화, 계정 인증·계정별 차단/초대 관리·정식 매치메이킹, 지형 차폐·은폐/정찰, 국가 점수·거점 승리, 배포·운영은 다음 단계다. 30초 이후 좌석 복구는 보장하지 않는다. 접속 순서 좌석은 시연 전용 가정이다.
