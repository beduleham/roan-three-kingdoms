# 보병·창병·궁병 공격 재생 개선 v0.1

## 문제

기존 공격 표시 기간은 4tick이었지만 프레임을 전체 전투 tick/2의 나머지로 선택했다. 공격이 임의 프레임에서 시작하고 4프레임 중 일부만 보일 수 있었다. 전투 코어는 공격 피해를 매 tick 기록하므로 매 이벤트마다 공격을 처음부터 재시작하는 방식도 한 프레임에 머무르게 한다. 이벤트 tick은 처리 후 상태 tick보다 앞서므로 원래 이벤트 tick만으로 프레임을 선택하면 첫 프레임을 건너뛸 수도 있다.

## 변경

- `apps/client/src/unit-motion.ts`: 공격 표시 시작 tick을 기준으로 0→1→2→3을 각 1tick씩 재생한다. `observeAttack`은 최초 관측 tick에서 시작하고 연속 피해 이벤트가 들어와도 현재 4tick 동작을 끝까지 유지한다. 다음 새 이벤트는 다음 동작을 시작한다. 마지막 이벤트 tick을 기억하여 소비한 이벤트를 재시작하지 않는다.
- 공격 동작 중 방향을 고정하여 도중에 다른 방향의 원화로 바뀌는 것을 줄인다. 다음 동작은 새 방향을 사용한다.
- `apps/client/src/main.ts`: 실제 ATTACK_HIT 관측만 표시 기록으로 만든다. 기존 초기화와 상태 피드백에 연결하여 패주·붕괴·전멸 시 공격 표시를 억제하고 초기화 시 기록을 비운다.
- `apps/client/test/unit-motion.test.ts`: 세 병종, 네 방향, 서로 다른 시작 tick 위상, 연속 이벤트, 중복·미래 이벤트, 재시작, 입력 복사 검증.
- `apps/client/e2e/demo.spec.mjs`: 실제 교전에서 4개 연속 tick의 프레임 0→1→2→3, 일시정지, 초기화 확인.

## 범위

기존 4방향 공격 원화를 재사용한다. 시각화용 400ms 동작 주기이며 전투의 공격 속도나 피해량·명중 tick을 바꾸지 않는다. 애니메이션은 이미 계산된 공격 이벤트에 대한 피드백이다. 원화의 예비·접촉 프레임과 실제 피해를 사전에 동기화하는 시스템은 아니다. 궁병 화살도 기존처럼 실제 이벤트 이후 표시하며 탄도·추가 피해를 만들지 않는다. 기병·장수의 전용 공격 원화, 전용 대기/피격/패주 동작과 프레임별 원화 일관성 개선은 남아 있다. 새로운 전투 기획 수치는 확정하지 않았다.
